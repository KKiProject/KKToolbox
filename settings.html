API 配置

Embedding API

Embedding 服务的 OpenAI 兼容接口地址，通常填写到 /v1 之前或 /v1。
用于调用 Embedding 服务，仅保存在 SillyTavern 扩展设置中。
生成聊天和世界书向量的模型名称。
从接口返回的模型列表中选择 Embedding 模型。

Reranker API

Reranker 服务地址；留空整组配置即可只使用向量排序。
用于调用 Reranker 服务的密钥。
对向量召回候选进行相关性精排的模型名称。
从接口返回的模型列表中选择 Reranker 模型。

副 API

生成自动总结、弹幕、剧情状态与地图册的 OpenAI 兼容接口地址，与主聊天 API 相互独立。
用于调用副 API 的密钥。
负责生成自动总结、弹幕、剧情状态与地图册的模型名称。
从接口返回的模型列表中选择副 API 模型。
自动总结
最近 N 楼保留原文并保持可见；已总结且离开该范围的楼层会用 ST 原生隐藏功能标记，可通过幽灵图标手动取消隐藏。
每次总结覆盖的楼层数量。旧楼层离开保留范围并攒够此数量后，由副 API 自动总结。
修复会补齐生成失败留下的缺失区间，并重做空白、截断或拒绝式摘要；重新总结会清除当前存档的插件摘要，并从第一批可总结楼层重新生成。
只重做与指定范围相交的现有摘要条目。例如每条摘要覆盖 15 楼，指定第 119 楼会重做包含它的整条摘要，不影响其他条目。
RAG 设置
临时关闭后，正文生成将跳过自动总结、聊天历史和世界书的向量召回与精排；不会删除任何向量或摘要，重新打开即可恢复。地图、人物发展、状态和手机回注不受影响。
每个向量片段的目标字数（中文字符）。在句子结束处自然断开，实际长度会有浮动。越小检索越精准但向量数量越多。
先由进入本轮的剧情总结圈定楼层，再从这些楼层的正文中初选至多这么多条；另保留少量全库候选兜底。世界书独立固定为 10 个候选。
最终发送给 AI 的正文细节片段上限，应不大于 top-K。剧情总结独立固定为初选 10 条、最多召回 3 条；世界书最多保留 5 条。
剧情总结、聊天正文与世界书分别精排后的最低相关度，越高越严格；未配置 Reranker 时不生效。
这不是必选项：蓝灯常驻条目本来就会发送给 AI，重复向量化容易浪费上下文；更推荐用于绿灯关键词条目很多、背景庞大的世界书，让插件按语义补充关键词没有触发到的相关内容。点击下方世界书名称可以展开，只选需要的条目，不必整本加入。自动总结已由剧情 RAG 管理，无需再次向量化。

在每次 AI 回复下方生成一个独立内容栏，单独调用一次副 API，不占用弹幕与状态栏的输出空间。
把玩家下一步可以说或做的事生成为可点击的游戏选项；点击后只填入酒馆输入框，不会发送。
可以只开剧情选项、只开自定义内容，或让两者共用同一次请求。

手机
关闭后，AI 回复、重刷和编辑正文都不再自动调用手机副 API；手机仍可正常使用，手动点“接收消息”也会照常更新。
